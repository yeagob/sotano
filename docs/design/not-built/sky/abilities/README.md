# Abilities of the sky: the animals' hindrances

Up: [The realm of the sky](../README.md)

The abilities are the hindrances the sky's animals use against the player: a kick, a slowing floor, a current, a freeze, a cage, a gust, a hole, a vanishing platform. The owner named them. Each one has its own document below. This README holds the rules every hindrance shares.

The animals hinder the player (owner direction). Each hindrance is a puzzle to answer, and the player always keeps a route up (rule 5 below).

Status: proposal. The rule that platforms which disappear always warn first is decided, and it is the model for every hindrance.

## 1. The shared rules

Status: proposal, except rule 4 (decided for platforms).

1. **Telegraph first.** Every hindrance shows itself before it takes effect: a sign the player can see or hear, lasting long enough to read. The length of the warning is a target in each document.
2. **Always with feedback.** A hindrance is never silent in its effect. The player sees what it does (the floor slowing, the water filling, the cage closing) and feels it (a push, a slowdown, a freeze).
3. **Nothing permanent.** A hindrance ends. Its effect dissolves after a few seconds, or when the player answers it. The original world's blocks come back, and the cubes an animal instantiates dissolve. The only exception is a block the player builds, which stays until a positive intention takes it away (realm [law 3.2](../README.md#32-blocks-the-player-makes-are-the-exception)).
4. **Platforms warn first.** Status: decided. A platform that disappears, or a part of it, always shows clear feedback that warns first.
5. **A route up is always there.** No hindrance takes away the player's way up. The floor always leaves a route the player can build or climb. Whether the player can go up from any point is open (realm, section 5).
6. **A hindrance is answered with the player's verbs.** The answers use the verbs the player already has: moving, jumping, building, and shooting. No hindrance asks for a new verb. If one ever does, the controls skill applies.
7. **Positive intentions answer every hindrance.** A positive shot always helps the player against a hindrance. A negative shot has no effect on the animal that makes it (realm law 3.3); whether a negative shot does anything to the hindrance itself is open.

## 2. What a positive intention does to each hindrance

Status: proposal. The owner has not decided the answers. These are the designed answers, to be checked.

| Hindrance | Document | A positive intention does (proposal) |
|---|---|---|
| Knockback | [KNOCKBACK](KNOCKBACK.md) | Turns the incoming kick into a soft push |
| Dense ground | [DENSE-GROUND](DENSE-GROUND.md) | Returns a dense cell to ordinary ground |
| Water currents | [WATER-CURRENTS](WATER-CURRENTS.md) | Turns the current's direction, or stops it for a moment |
| Paralysis | [PARALYSIS](PARALYSIS.md) | Shortens the freeze once the player holds a steady aim |
| Cube cage | [CUBE-CAGE](CUBE-CAGE.md) | Breaks the cage faster than an ordinary shot |
| Wind | [WIND](WIND.md) | Lets the player build a wall in the gust's line |
| Opening holes | [OPENING-HOLES](OPENING-HOLES.md) | Closes a hole that has started to open |
| Fading platforms | [FADING-PLATFORMS](FADING-PLATFORMS.md) | Holds a fading platform for a moment |

## 4. Open questions

1. **Which animal uses which hindrance.** The owner named the hindrances, not the animals that use them. The proposals above are open.
2. **Damage.** Whether a hindrance does damage, or only moves and holds the player.
3. **The warning length.** The targets for each warning are set by the design agent (see [guardians](../guardians/README.md)).
4. **Negative shots at hindrances.** Whether a negative shot does anything to a hindrance itself.
