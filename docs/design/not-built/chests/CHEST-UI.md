# Chest contents: pop-out or menu

Up: [not-built chests](README.md) · Status: proposal, open question.

The build spits a chest's contents onto the floor in front of the player: pickups and practices land, and the player collects them. The design recommended this (no menus, it fits one-block carry). The owner has not ruled on a grid menu instead.

## The two readings

- **Pop-out (built).** Contents leap out one by one, land in front of the player and wait to be collected. No screen opens.
- **Grid (not chosen).** A small Minecraft-style grid opens with the contents, and the player takes them one at a time, or several at once.

## What would change

- A grid would need a screen, a way to close it, and the controls for it (a new control set, see the controls skill).
- Pop-out keeps the chest animation as the only reward moment; a grid would replace it or join it.

## Open questions

1. Keep pop-out, or add a grid for chests that hold several things?
2. If a grid comes, does it also hold the stored blocks of [CHEST-STORAGE](../../not-built/elements/CHEST-STORAGE.md)?
